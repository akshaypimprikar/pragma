## [2.1.2] — 2026-11-12

### Added
- **`/gates` runs as one script (`scripts/check_gates.sh`).** It runs the pre-step and Gates 0-11 and prints the Gate summary block itself, so no model retypes results that `/review` then has to re-check. The model keeps only the judgment steps: filling an empty CHANGELOG, running `security-review` when Gate 7 prints `[!] Security`, weighing Gate 8's advisory candidates, and candidate invariants. Project settings move to a new `gates` key in `scripts/pipeline_lanes.json` (scheme, destination, `sensitive_paths`, UI-test folders, and Gate 10 `rules` as JSON regex entries); `setup.sh` copies the script and fills the scheme. An unset scheme fails Gates 1-2 instead of skipping them. Gate 6 now reads coverage for new files from Gate 2's result bundle (no second test run), and Gate 10's UI-selector check, which used to be done by hand, is scripted: a selector must appear as a string in the app or be text the tests type. Gate 9 is skipped on a branch that adds no `.swift` file (nothing to check), so an unconfigured layer list fails only once Swift is added; pragma's own PRs had been hand-reporting that case as skipped against the SKILL's `[✗]` rule. `gates/SKILL.md` keeps the gate headings and judgment steps and drops the inline commands; `/review` re-runs Gates 3, 4, 5 and 10 with the base branch's copy of the script and config. The `scripts/check_*` name puts it under the guard hook and Gate 11, and the two helpers it runs (`scripts/detect_build_target.sh`, `scripts/select_simulator.py`) are added to both guard lists and the small-PR excludes. Existing installs: add the `gates` key and copy the script at the next `/sync-workflow`.
- **The guard hook also runs in Codex CLI.** `scripts/install_guard_hook.py` (run by `setup.sh` and `/pragma:init`) now also registers `.claude/hooks/guard_protected_paths.py` in `.codex/hooks.json`. Codex reports file edits as `apply_patch` with the patch in `tool_input.command`, so the hook reads its `*** Add/Update/Delete File:` and `*** Move to:` paths, indented or not, as Codex does. A patch run through Bash (`apply_patch` or `applypatch`, or any `*** Begin Patch` body) is checked too, best effort: its paths are resolved against the session cwd and every `cd`/`pushd` target in the command, but not against variable-built paths. Codex has no `$CLAUDE_PROJECT_DIR`, so the entry finds the hook from the git root, including the project's own path when it sits below it (an `ios/` folder). `.codex/hooks.json` and `.codex/config.toml` join the guarded files in the hook and in `check_gate_integrity.py`. Before this, Codex 0.166.0 on a `feature/*` branch edited `CLAUDE.md` with the guard installed and nothing blocked it. Codex runs a project hook only after the user trusts it (`/hooks`). New `scripts/tests/test_install_guard_hook.py` (7 tests, including the registered Codex command blocking an `apply_patch` to `CLAUDE.md`, also for a project below the git root) and 20 new hook self-test cases.
- **Review stage contract (`scripts/review.schema.json`, `scripts/check_review_contract.py`).** One JSON shape for what a `/review` run returns in any agent CLI: reviewed SHA, round, lane, runtime (CLI, version, model, sandbox, network), gate checks, isolation, findings in `review_verdict.py`'s format plus path, line, quoted evidence and fix, verdict, coverage, limitations and where it was posted. Every object lists all its properties as required and allows no extras, so the schema can also go to `codex exec --output-schema` or `claude -p --json-schema` (not yet tested with either). The script validates against the schema file and then checks what a schema cannot: a full SHA that matches `--head`, a verdict that matches `review_verdict.py` and any failed gate check, an `isolated` claim with evidence, and a reason for every skipped check and unposted review. It does not change `/review` yet; it is the pass/fail check for running `/review` with no Claude (Codex first). `scripts/tests/test_check_review_contract.py` covers it.
- **Install links each skill into `.agents/skills/` for Codex.** Codex CLI lists skills from `.agents/skills/`, not `.claude/skills/` (0 of 17 pragma skills found there with Codex 0.160.0). `scripts/sync_skills.sh`, which `setup.sh` and the plugin `init` both run, now adds one relative symlink per skill, `.agents/skills/<name>` → `../../.claude/skills/<name>`, so `.claude/skills/` stays the only copy. A project's own `.agents/skills/` entries are left alone, with a warning when one has a pragma skill's name, and a whole-directory link to `.claude/skills` is left as is. If `.agents` or `.agents/skills` is a symlink elsewhere, a file or a broken link, the install warns and skips the links instead of writing dangling ones or stopping. `scripts/tests/test_agents_skills_links.py` covers this. Only skill discovery is checked so far; a full Codex run of a skill is still to come.
- **Opt-in install of Apple's Xcode 27 Agent Skills (`scripts/install_apple_skills.sh`, `setup.sh --apple-skills`).** Xcode 27 ships Agent Skills that `xcrun agent skills export` writes to disk (11 on Xcode 27.2 27B52). The script exports them from your own Xcode and installs an allowlist to `~/.claude/skills`, where Claude Code loads them when a prompt matches. Measured 2026-11-01 with Sonnet: given a `@State` init error, Claude Code called `swiftui-whats-new-27` on its own in 5 of 5 runs (project-level and user-level folders) and gave Apple's fix; without the skill it called `@State` a property wrapper in 4 of 4 runs. The files carry no license header, so pragma never vendors them and never installs them into a project. Off by default; setup continues if the export fails or Xcode is older than 27. Codex was not tested.

### Fixed
- **A hardware-dependent coverage exception could skip an unrelated file.** `scripts/check_coverage.py` and Gate 6 in `scripts/check_gates.sh` matched `HARDWARE_DEPENDENT_EXCEPTIONS` with a bare suffix test, so an exception for `Services/Bar.swift` also skipped `App/FakeServices/Bar.swift`. Both now match only on a `/` boundary (or the exact path). FinanceTracker fixed `check_coverage.py` on 2026-09-23 but the fix never reached pragma; found in FinanceTracker #206.
- **`scripts/check_gates.sh` exited 0 when Gate 7 asked for a security review.** A `[!] Security — security-review required` row left the exit code at 0, which `gates/SKILL.md` defines as "every blocking gate passed", so a caller that reads only the exit code saw all clear. The script now exits 4 when every blocking gate passed and Gate 7 printed `[!]`; a blocking failure still exits 1. Found in FinanceTracker #204.
- **Gate 10 hid why it failed when its check crashed.** If the Gate 10 Python block died (unreadable config, a rule without `pattern`, an invalid regex), the row read `0 violation(s)` and the traceback went to stderr, outside the report. The traceback now prints in the Gate 10 details and the row reads `check did not run (see report)`. It already failed closed. Found in FinanceTracker #207.
- **`scripts/check_pr_lane.py` could put a PR in a lighter lane when a path had non-ASCII characters or a newline (#160).** `git diff --name-only` printed such a path quoted and escaped, so it matched no lane glob, and `**` did not match across a newline. The script now reads `git -c core.quotepath=false diff -z --name-only` and matches globs with `re.DOTALL`. `scripts/check_gates.sh` had the same gap: git quotes a name with a `"`, `\`, tab or newline even with `core.quotepath=false`, so Gates 3, 6, 7, 8 and 10 silently skipped such a `.swift` file, and Gate 10's UI-selector check crashed on one. Its path lists now come from `-z` output, and a changed path with a newline in its name fails a new `File names` row in every run, since the gates pass paths one per line.
- **`/pragma:init` did not copy `scripts/check_gates.sh` or the file-registration scripts (#133).** `.claude/commands/init.md` listed fewer scripts than `scripts/setup.sh`: `check_gates.sh`, `detect_file_registration.sh`, `register_files.rb` and `check_file_registration.py` were missing, so `/gates` could not run in a project installed through the plugin. It also named the three copied test files only as a `test_check_*.py` glob. `init.md` now names every file `setup.sh` copies, and new `scripts/tests/test_install_parity.py` fails when the two lists differ.
- **README manual install copied pragma's own context logs (#151).** It said to copy `.claude/context/`; it now points to the `scaffold/.claude/context/` templates. The CI section no longer says the agent judges Gate 10's UI-selector cross-check: `scripts/check_gates.sh` runs it (#156).
- **Gate 5 passed an empty `[Unreleased]` section with CRLF line endings or link definitions (#164, #165).** A CRLF blank line (`\r`) and Keep-a-Changelog link definitions at the end of the file (`[Unreleased]: https://...`) counted as entries. `scripts/check_gates.sh` and the `deterministic-pr-gates` skill now strip `\r` and skip link definitions. `scripts/tests/test_check_gates.py` covers both, plus a real entry under `### Added` and an entry in a last section (#166). FinanceTracker has the same code (and FinanceTracker #210 for `/status`); port at the next `/sync-workflow`.
- **`/status` miscounted `[Unreleased]` entries (#163).** It read a fixed 20-line window, so it showed 22 of pragma's 26 entries and could show 0 for a long section. It now counts bullets up to the next `## ` heading.
- **Gate integrity read the wrong path from a crafted file name (#159, #170).** `scripts/check_gate_integrity.py` took each path from the `diff --git a/... b/...` header with a greedy regex, so a name holding ` b/` was cut at the last ` b/`. On a `feature/*` branch, a new `scripts/check_x b/y.py` was read as `y.py` and passed check #1, and a suppression in `Sources/a b/b.swift` was reported as `b.swift`. A header git quotes (a name with a quote, tab, backslash or control character) did not match the regex at all, so that file was skipped. Paths, status and rename sources now come from `git diff -z --name-status`. Each diff block is matched to its path by the exact header git prints for that path, and a block that matches no path stops the run (exit 2). Git output is decoded from bytes rather than with universal newlines, so a bare `\r` in a line or a path can no longer start a fake block or break a match. The forced-text re-fetch also runs with `--literal-pathspecs`, so a masked file named like `:(top)x.swift` is no longer skipped. The suppression, stub and threshold scans split the diff on `\n` only: `splitlines()` also broke on `\r`, `\x0b` and U+2028, so `let a = 1\r// swiftlint:disable all` was never checked (#170). New `scripts/tests/test_check_gate_integrity.py` (10 tests). Found by the security-review plugin during #155. FinanceTracker has the same code; port at the next `/sync-workflow`.
- **Gate 5 passed an empty `[Unreleased]` section.** `scripts/check_gates.sh` and the `deterministic-pr-gates` skill read the 10 lines under `## [Unreleased]`, so an empty section followed closely by a release heading counted that release's bullets as entries. Both now read only up to the next `## ` heading and ignore `###` subheadings. Found in the FinanceTracker #201 review (F1); `scripts/tests/test_check_gates.py` covers it.
- **A fresh install inherited pragma's own context logs.** `setup.sh` and `/pragma:init` copied pragma's `.claude/context/*.md` into the new project, so it started with pragma's 6 releases in `feature-log.md`, 1 decision in `decisions.md` and 43 rejections in `rejections.md` (checked 2026-11-05 with `setup.sh` on an empty folder). These were empty templates when `setup.sh` was written; pragma began logging to them in August. Both installers now copy `scaffold/.claude/context/`, which holds each file's header and format comment only. Existing context files are still never overwritten. New `scripts/tests/test_context_templates.py` (4 tests) checks the fresh install, the skip, `init.md`, and that each template matches the header of pragma's live file, so a format change in one fails until the other matches.
- **A shell-run `apply_patch` could get past the guard hook.** The hook read patch headers from the command text. On a `feature/*` branch, `printf '...\n*** Update File: CLAUDE.md...' | apply_patch` and `apply_patch "$(cat p.patch)"` were allowed (found in FinanceTracker #198's review). Two rounds of deciding which shell forms were readable each left a bypass: a decoy header, a stray `Begin Patch` argument, or an unquoted heredoc that expands `$(cat f)`. So the shell route is now closed on `feature/*`, by an allowlist: a Bash command that names `apply_patch` or `applypatch` is blocked when the session's directory, or any directory the command `cd`s into, is on a `feature/*` branch, unless every command in it (including inside `$( )` and single-level backticks) is a read-only tool, and it has no unquoted heredoc with a `$( )` or backtick, no nested backticks, no arithmetic (`$(( ))`, `$[ ]`), no `${...}` other than a plain `${name}`, no `$( )` or backtick stored in a quoted string or assignment, no unquoted brace expansion (`{x,y}`, `{a..b}`), and no assignment whose value names the tool. The read-only tools are: `grep`, `egrep`, `fgrep`, `rg` (without `--pre`, `--hostname-bin` or `-z`/`--search-zip`, which run another program), `echo`, `printf`, `cat`, `type`, `which`, `sed -n` with one print-only script (no `-e`/`-f`), `find` with no `-exec`/`-ok`/`-delete`/`-fprint` action, `git commit` or `git log` with no global options or `--output`/`--ext-diff`/`--textconv`/`--template`, no `NAME=value` prefix on any of these, and only literal arguments (no `$`, backtick, brace or unquoted glob) for `sed`, `git`, `rg`, `find`, `command` and `printf`, and `command -v`/`-V`. A command with an output redirection (`>`, `>>`, `>|`, `&>`, `&>>`, `<>`, `>& file`) to anything but `/dev/null` is not read-only, because a file written there can be run by the same command (`echo apply_patch > tool.sh; rg --hostname-bin=./tool.sh ...`, or appending to `.git/hooks/pre-commit` before `git commit`, #146); input redirections and `2>&1`-style descriptor copies are still allowed. The name is found in any letter case, and when split by quotes, backslashes or a backslash-newline, `${x:-...}` defaults, brace expansion (nested groups, ranges, quoted braces), `$'...'` escapes (an escape Python cannot decode counts as naming it), `$''`/`$""`, a `$( )`, backtick or `$@` that prints nothing, a glob of at least 5 letters (any glob as the command word), including a bracket glob with a quoted or escaped member such as `apply_pa[x\]t]ch` or `apply_pa[x']'t]ch`, also when mixed with the forms above (`./apply_p${u}a[x']'t]ch`, #145); and a brace group beside a glob is read as `*`, any of its alternatives (`./apply_p{a,b}[x']'t]ch`), or across variables the command sets (`a=apply_; ${a}patch`, `a+=`, `printf -v`, `read`, `set --`). These forms are self-test cases and were fuzzed against real bash; the detection is an over-approximation, not a shell parser. A Bash command over 32 KB is blocked on every branch before any analysis, because some of the analysis is not linear and a hook that times out fails open. Five review rounds of listing the ways a shell can run the tool (wrappers, `xargs`, stdin-fed shells, `/dev/stdin` paths) each left a bypass, so anything not on the list now counts as a possible run. Codex's `apply_patch` tool is unaffected, and its file list is still checked per file. Off `feature/*`, shell patches still have their headers checked against protected paths, including headers joined by a literal `\n`. Tradeoff: on `feature/*`, a harmless command that mentions the tool but is not on the list is blocked too (`bash build.sh; grep apply_patch log`, `sudo grep apply_patch f`, `ls | xargs grep apply_patch`, `grep apply_patch "$(echo f)"`, `grep apply_patch log > out.txt`); split it, use the Write tool for a file that mentions it, or run it on a `chore/*` branch. Known limits: a name that is printed at run time (`$(echo pa)`, `base64 -d`), a `*` standing for more than one letter inside a brace expansion, a short glob inside a `bash -c` string or `find -exec` (#142), a command that never names the tool (a script file such as `bash p.sh`, another language such as `python3 -c`) is not seen, nor is a script written by one command and run by a later command that does not name the tool (`git commit` running a hook written earlier), and `cd ~`, `cd -` and `cd $VAR` are not followed (#139). 216 new hook self-test cases. One #136 case, a shell heredoc patch of an ordinary file on `feature/*`, now expects a block.
- **`/review` could claim an isolated review that never ran.** Under Codex CLI 0.160.0 the skill spawned no subagent (it names only Claude Code's Agent tool) and the verdict still said "the isolated review found no defects". The skill now names Codex's `spawn_agent` with `fork_turns: "none"` as the equivalent and says the verdict is `NOT isolated` unless a subagent's report is the one posted.
- **Installed projects were missing the scripts `/review` runs.** `/review` calls `scripts/review_verdict.py` and `scripts/check_finding_lines.py`, but neither `setup.sh` nor the plugin `init` copied them, so the step failed in any project pragma installed.
