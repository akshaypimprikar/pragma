# Changelog

All notable changes to this project are documented in this file.

## [Unreleased]

### Added
- **Guard hook for gate-definition files (`scaffold/.claude/hooks/guard_protected_paths.py`)**, ported from FinanceTracker's tested version and made generic. A `PreToolUse` hook that blocks `Write`, `Edit`, `MultiEdit` and best-effort `Bash` writes to skills, `AGENTS.md`, `CLAUDE.md`, `CONSTRAINTS.md`, `.claude/context/invariants.md`, `.claude/settings.json`, `.claude/hooks/*` and `scripts/check_*` on `feature/*` branches, at the repo root or under any subdirectory. `setup.sh` and `/pragma:init` install it through the new `scripts/install_guard_hook.py`, which merges one entry into an existing `.claude/settings.json` without touching its other hooks or permissions (it backs the file up first, is a no-op on re-run, replaces an older or narrower guard registration with the current one, and leaves an invalid or oddly shaped file untouched). The hook's self-test also checks that its glob list matches the CI script's, and a new `gates` job step in `pr-checks.yml` runs it. The `paths:` filter now also lists each guarded file as `**/…` so a PR touching only a nested one still triggers the job. Installed by default; `setup.sh --no-guard-hook` skips it. Closes the "no native guard" limitation in `/gates`.
- **AGENTS.md support, and the 16 consumer-facing commands migrated to Agent Skills — breaking change for existing installs.** `setup.sh` and `/pragma:init` now generate `AGENTS.md` (the open cross-tool instructions-file convention Claude Code added support for in v2.1.277, 2026-09-18) with a one-line `CLAUDE.md` importing it (`@AGENTS.md`), instead of generating `CLAUDE.md` directly — an existing real `CLAUDE.md` is never touched. `.claude/commands/*.md` (Claude Code-only) is replaced by `.claude/skills/<name>/SKILL.md` — the SKILL.md format, an open standard (Anthropic, Dec 2025) also read natively by Cursor, GitHub Copilot, Windsurf, Zed, and others from that same path; each migrated skill sets `disable-model-invocation: true` (honored by Claude Code, Cursor, Copilot, and Zed) to keep today's explicit `/name` invocation, not auto-trigger. `init.md` and `pragma-review.md` stay pragma-repo-only meta-commands under `.claude/commands/`, unchanged — neither is copied to a consuming project. `skills/deterministic-pr-gates/` moves to `.claude/skills/deterministic-pr-gates/` for one canonical skills location. **Migration for an existing install:** re-running `setup.sh`/`/pragma:init` now detects any `.claude/commands/<name>.md` left over from a pre-skills pragma version, backs it up to one consolidated `.claude/commands.bak-<timestamp>/`, and removes it, so it can't shadow the new same-named skill — check the backup if you'd customized one, and re-apply into the matching `.claude/skills/<name>/SKILL.md`. `scripts/check_gate_integrity.py`'s `GATE_DEFINITION_FILES` and `scaffold/.github/workflows/pr-checks.yml`'s trigger paths were both updated to the new location — verified locally: a throwaway edit to `.claude/skills/gates/SKILL.md` on a `feature/*` branch is still caught by gate-integrity (and correctly not caught on a `chore/*` branch), and `setup.sh` was run twice against a scratch directory seeded with a pre-skills `.claude/commands/gates.md` — the first run migrated and backed it up, the second was a clean no-op. After merging in the now-landed `claude plugin eval` suite (PR #73): a 1-run-per-case smoke test (`--runs 1 --ablation none`, not the full 3-runs-per-arm comparison) confirms the plugin loads and every case runs cleanly post-move — no "skill not found" or load error from the `.claude/skills/deterministic-pr-gates/` relocation. `deterministic-pr-gates` didn't fire in this run on 3 of 4 cases, matching (not regressing from) the pre-migration baseline logged above, which already recorded 0/3 and 1/3 fire rates on the same cases — one run each is too small a sample to separate "unaffected by the move" from "the already-known low trigger rate," but nothing here indicates the move broke it. **What this does not claim:** no README wording states the pipeline has been run on Cursor, Codex, or any tool besides Claude Code — cross-tool compatibility rests on those tools' own documented support for AGENTS.md/SKILL.md, not on pragma having been tested against them. Each tool's own plugin-marketplace mechanism (Cursor's `.cursor-plugin/marketplace.json`, Codex's, launched 2026-03-27) is deliberately not added here — both already auto-discover `.claude/skills/` without one.
- **`/review` now verifies `/gates` instead of trusting its pasted summary** — compares the summary's `Gates run at <sha>` line to the PR HEAD SHA, re-runs the deterministic gates (the gate-integrity and TDD-order scripts from the base branch, plus the grep-only gates) at that SHA, and requires a `gates` CI check (or notes it is not yet configured). The context-continuity paragraph now states plainly that `/review` is not independent of the implementer's context by default and recommends a fresh session for isolation. Adds one advisory checklist item for adaptive layout and `#available` gating.
- **`/gates` hardening (templated)** — clean-tree + `git rev-parse HEAD` pre-step; Gate 0 also triggers on `*.pbxproj`, `*.xcconfig`, `Info.plist`, `*.entitlements`, `Package.resolved`; Gates 1-2 fail on a non-zero `xcodebuild` exit, an empty log, or zero executed tests (they no longer pipe into `xcsift`); Gate 10's type-safety example covers declaration, return-type, literal and conversion forms and states it is a regex heuristic, not an AST check; the gate summary starts with `Gates run at <sha>`.
- **`docs/xcode-27-sdk-migration.md`** — short, cited note on two Xcode 27 SwiftUI source-compatibility patterns (`@ContentBuilder` overload ambiguity, `@State` macro), linked from Gate 1 as advisory failure guidance. Sourced to AvdLee/SwiftUI-Agent-Skill by file and line; not reproduced by pragma.
- **Scaffold `gates` CI job (`scaffold/.github/workflows/pr-checks.yml`)** — re-runs `check_tdd_commit_order.py` and `check_gate_integrity.py` from base-branch copies against the PR head, so a PR cannot edit the scripts that judge it; falls back to the head copy with a `::warning::` only when the base branch lacks a script (the install PR). It blocks a merge only if the repo marks `gates` a required status check.
- **`setup.sh` and `/pragma:init` refuse to install into pragma itself** (symlinks resolved with `pwd -P` / `-ef`) and back up a project's differing `.claude/commands/` files to `.claude/commands.bak-<timestamp>/` before overwriting them.
- **`evals/` — first `claude plugin eval` suite** — four read-only cases for the `deterministic-pr-gates` skill (broad "ready for a PR?" question, docs-only branch, plan to weaken a gate to get green, unrelated question), each run with and without the plugin. First review pass (2026-09-21) found defects in the graders and prompts. They are fixed: the broad prompt said the repo was unavailable, which stopped the skill firing; the docs-only prompt never asked how to report a skipped check, so that grader could not pass; the `says-skip` regex missed "isn't necessary", which caused the 0.50 vs 0.00 gap first put down to noise; the Gate 0 grader checked for a phrase, not for order; two graders were near-empty. Latest results (2026-09-23, Claude Code 2.1.278, 3 runs per arm): with pragma vs without, broad 1.00 vs 0.22, docs-only 1.00 vs 1.00, weakening a gate 0.44 vs 0.33, unrelated 1.00 vs 1.00. The skill fired on 3 of 3 runs for the broad and docs-only prompts and 0 of 3 for the weakening prompt. 3 of 4 cases pass, so the suite exits 1 at the default threshold. Three runs per arm is too few to call small differences real. See `evals/README.md`. The `.gitignore` keeps `evals/results/` out of git.
- **`CONSTRAINTS.md` — a per-project config file for platform-tunable quality dimensions**, separate from `gates.md` so a platform-specific or project-tunable check doesn't need to be hardcoded into the gate prose. Additive only: build/test/security stay exactly where they are today (`CLAUDE.md` + `gates.md` Gate 1/2/7) — this file does not duplicate them. Ships with one Floor dimension (`gate-integrity`, below) and two documented-but-commented-out opt-in dimensions (a coverage ratchet, and a platform-specific accessibility check) as seams for future work rather than speculative implementation.
- **`/gates` Gate 11 (pipeline) / Gate 10 (`deterministic-pr-gates` skill) — gate integrity (floor-guard)**, via new `scripts/check_gate_integrity.py`. Detects gate-weakening on the branch diff: a gate-definition file edited on a `feature/*` branch, a previously-existing test deleted instead of fixed, a new suppression/skip marker (`swiftlint:disable`, a Swift Testing `.disabled()` trait, `XCTSkip`), an unfinished stub newly added to shipped code, or a numeric threshold in a gate-definition file lowered by the diff. Closes the diff-detectable half of `gates.md`'s self-documented "known limitation" (no native guard against self-modifying guardrail files) — it cannot block the edit mid-session (that needs a `PreToolUse` hook, a separate architecture piece), only catch it once `/gates` runs. Sourced from `addyosmani/agent-skills`' `constraint-driven-development`/`floor-guard` pattern, surfaced in the 2026-09-09 pragma-vs-agent-skills gate-by-gate diff.
- **`/feature` — opt-in doubt-driven review before the GREEN commit.** When a task introduces a new protocol declaration or adds/modifies a mutation on an `@Model` type (the same shapes Gate 8 and Gate 10 already check for), a fresh-context subagent reviews the diff plus the task's acceptance criteria — not the implementer's reasoning — and is instructed to find problems or state it found none, bounded to 2 rounds. Real findings log to `.claude/context/incidents.md` (lazy-created on first use, matching `/bugfix`'s existing convention). Exists because `/review` is deliberately not blind to the implementer's reasoning (see `review.md`'s "known tradeoff" section) — nothing else in the pipeline catches a bad call while it's still cheap to reverse. Also sourced from the `addyosmani/agent-skills` diff (`doubt-driven-development`), scoped down to single-model only for this pass — no cross-model escalation.
- `scripts/setup.sh` now copies `CONSTRAINTS.md` and `scripts/check_gate_integrity.py` into new projects.

### Changed
- **Gate integrity check 1 now covers every file the guard hook protects**, not only `GATE_DEFINITION_FILES`: any `.claude/skills/*/SKILL.md`, `AGENTS.md`, `CLAUDE.md`, `CONSTRAINTS.md`, `.claude/context/invariants.md`, `.claude/settings.json` and `.claude/hooks/*` edited on a `feature/*` branch now fails the check (new `GUARDED_PATH_GLOBS`). Before, editing `review/SKILL.md`, `settings.json` or the hook itself by a plain commit and push passed CI. Checks 2 to 5 are unchanged. The `pr-checks.yml` `paths:` filter gains the same files, so a PR that only touches them runs the `gates` job (it also runs the macOS `unit-tests` job).
- **`/pragma-review` now runs on `claude-sonnet-5` instead of `claude-haiku-4-5-20251001`.** Two of its four checks need judgment, not a grep: deciding whether a changed section should use `<placeholder>` tokens, and spot-checking doc accuracy. A missed leak ships in a public template. Sonnet 5 costs twice as much per token as Haiku 4.5 and half as much as Opus 5.5 (first-party list prices), and it supports effort control. `/gates` and `/release` stay on Haiku: their work is mechanical.

### Fixed
- **Two real bugs in this PR's own AGENTS.md/skills migration, both found by `code-review:code-review` run against this PR**: `init.md`'s skill-copy step promised the same compare-and-backup-before-overwrite behavior `scripts/setup.sh` implements, but its bash block was a bare `cp -r` with no comparison or backup at all — an agent following the fenced block literally, rather than re-deriving the missing logic from the prose above it, would silently overwrite a customized skill file. Fixed by giving `init.md` the same `cmp`-based comparison-and-backup logic `setup.sh` already has, so the two installers can't drift on what counts as "customized." Separately, `setup.sh`'s new old-command migration step computed its backup directory's timestamp inside the per-file loop rather than once before it; at `date`'s 1-second resolution, migrating 2+ old command files in one run mostly collided on the same timestamp and scattered them across several separate `-x`-suffixed backup directories instead of one consolidated backup (not data-lossy — every file was still copied before removal — just confusing). Fixed by computing the backup directory once, before the loop, in both `setup.sh` and the now-corrected `init.md`.
- **`check_gate_integrity.py`'s lowered-threshold check (check #5) could be defeated by a trivial reword** alongside the actual percentage drop, found by `code-review:code-review` on this PR: `paired_threshold_drops()`'s content-based pairing normalized out the percentage value but still required the rest of the line to match exactly, so a removed/added pair that was both reworded ("must be" → "should be") *and* had its threshold lowered produced two different normalized strings, failed to pair, and the drop was silently never flagged. Fixed with a similarity-based fallback (`difflib.SequenceMatcher`, floor 0.5) for pairs that don't match exactly, so a reworded-plus-lowered line is still caught while genuinely unrelated lines don't false-pair — verified directly against both cases plus the original exact-match path.
- **`gates/SKILL.md`'s Gate 2 test-count regex only matched XCTest's `Test Case '…' passed` line format**, not Swift Testing's own console output (`✔ Test "…" passed …`), found by `code-review:code-review` on this PR — a fully green Swift Testing suite would read zero executed tests and fail the gate that exists specifically to catch a test filter matching nothing. Broadened to match both formats and both common checkmark glyphs; this has not been confirmed against every Xcode version's exact wording, so the file now says explicitly to run it once against a real green suite before trusting it.
- **`.claude/commands/init.md`'s file-copy list (the `/pragma:init` plugin install path) never picked up `check_gate_integrity.py` or `CONSTRAINTS.md`**, even though `scripts/setup.sh`'s equivalent list did — a project installed via the plugin path would have gotten Gate 11 wired into its `gates.md` with no script to run it, failing immediately. Added both to `init.md`'s step 3 and its `Done when` criteria.
- **`check_gate_integrity.py` (Gate 11 / gate-integrity) had 18 numbered fixes: 15 from three `code-review:code-review` passes (`b360ed4`, `f93744e`, `0ab47f2`, 5 each), 2 from self-runs (`9795898`, `ab205aa`), and 1 from a test written to verify an earlier fix (`9949b3a`) — landed via PR #66 (1 fix) and PR #67 (the other 17)**, all fixed before release. "Fixes", not distinct bugs: some re-fix the same defect, and `b360ed4`'s six-item list repeats `9795898`'s, so that one is counted once. The three passes were not equal: `f93744e`'s own message says only 2 of 7 review dimensions completed before a spend limit hit (`0ab47f2` re-ran and completed all 7), and `b360ed4`'s message says it reviewed "this PR" and predates #66's merge, but it merged via #67. The items through `f93744e` and `9949b3a`: the suppression/stub scan matched this file's own docstring and other markdown prose describing the patterns, not just real code — excluded `.md`/gate-definition files/`scripts/` from that scan; `current_branch()` returned an empty string in detached-HEAD state (how most CI PR checkouts work), silently disabling the feature-branch check with no warning — now checks `GITHUB_HEAD_REF` first, falling back to `git rev-parse --abbrev-ref HEAD` (matching `capture_pipeline_metrics.py`'s existing convention), which returns the literal `HEAD` in detached state rather than an empty string, so that state is explicit, not silent; no error handling around any git subprocess call, so a missing base ref or shallow clone crashed with a raw traceback — wrapped in a clear, actionable error message; the `.disabled(` suppression pattern also matched SwiftUI's `.disabled(condition)` view modifier, not just the Swift Testing trait — scoped to test-file paths only; the lowered-threshold check compared a global minimum percentage across a whole file diff instead of pairing the actual changed line, which could false-positive on an unrelated number or mask a real change — rewritten to pair removed/added lines by normalized content within each diff hunk (a test written to verify that fix found the pairing itself compared the diff-marker prefix, not the content, and never matched at all — fixed to strip the marker first, in `9949b3a`); the bare-stub pattern required an entire added line to be just `fatalError()`, missing common one-line idioms like `default: fatalError()` — un-anchored to match anywhere in an added line, excluding calls with a message; a later fix over-corrected and dropped detection of `fatalError("not implemented")` (a message alone doesn't make a stub legitimate — only a real, specific reason does) and narrowed `swiftlint:disable`/`XCTSkip` detection to test files only (only `.disabled(` needed that scoping); `is_test_path`'s `"Tests"` substring check both over-matched (`ABTestsManager.swift`, a feature-flag file) and under-matched (`AuthManagerTest.swift`, singular, no underscore) — replaced with a suffix-anchored regex. Also consolidated ~1 git subprocess per changed file down to two calls total, and narrowed the `scripts/` exclusion to gate-definition scripts only, closing an evasion gap. `0ab47f2`'s five further fixes: the threshold check only compared the first percentage on a line, not a second one on the same line; the bare-stub pattern missed `fatalError("")`; the `scripts/check_` exclusion exempted every sibling `check_*.py` script's real code, not just this file's own path; branch detection had no override for CI other than GitHub Actions `pull_request` runs (added a branch argument); and the git error handler blamed `BASE_REF` even when it wasn't in the failing command. Documented, not fixed: a gate-definition file or test renamed away rather than deleted isn't tracked across the rename (pre-existing, not introduced by this work).
- **The same gate-integrity rationale and pattern list was duplicated near-verbatim across `gates.md`, `SKILL.md`, and `CONSTRAINTS.md`** — three sources of truth for one description, the exact anti-pattern `CONSTRAINTS.md`'s own intro warns against. Trimmed `gates.md` Gate 11 and `SKILL.md` Gate 10 to a brief pointer; `CONSTRAINTS.md`'s `gate-integrity` entry is now the canonical full description.
- **`feature.md`'s autonomous-loop stop condition still enumerated only 7 of 11 gates** after PR #66 appended "gate integrity clean" to an already-incomplete list (missing coverage, security, abstraction bloat, and architecture compliance) — reconciled against `gates.md`'s fully-enumerated version of the same condition.
- **Gate 11's documented invocation (`python3 scripts/check_gate_integrity.py`, no argument) silently defaults to diffing against `develop`**, which is wrong on a `release/*`/`hotfix/*` branch (PRs against `main`) — documented the explicit `main` argument to pass in that case, in both `gates.md` and `CONSTRAINTS.md`.
- **README CI claims corrected** — three places said CI independently re-runs "the same checks" as enforcement "that can't be bypassed"; CI ran the tests and coverage but neither gate script, and required checks are opt-in. The README now states what the `gates` job re-runs, what it does not, and how to make it required. It also states what `/review` re-runs and that `/review` shares a session with the implementer by default.
- **Stale wording:** the `deterministic-pr-gates` skill no longer claims nothing asks a model to opine (Gate 7 is a review skill or manual pass; Gate 8 is advisory); plugin and marketplace descriptions say "CI checks"; `/test` and the skill's Swift example capture `xcodebuild`'s exit status instead of piping to `xcsift`; "Swift-change pre-check" is now "build-relevant change check", matching Gate 0.

The `check_gate_integrity.py`/`init.md`/`feature.md`/Gate-11-base-ref items above were originally logged as two separate, partially contradictory passes over the same work (one counting six bugs, one counting eight, disagreeing on the exact fix for two of them) — consolidated here into one description matching the code as it actually stands, verified by reading the current implementation rather than either historical count. All found via `code-review:code-review` passes, self-runs and one test-found fix, across PRs #66 and #67, counted in the `check_gate_integrity.py` entry above, before any of it was released.

## [1.2.0] — 2026-08-17

### Added
- **`/pragma-review` command** — pragma has no `CLAUDE.md`, `Views/`, or architecture layers for FinanceTracker's Swift-shaped `/review` agent to check, but every non-`/sync-workflow` pragma PR was merging with zero automated check and no auditable GitHub review trail. Checks template-literal leakage, `<placeholder>` convention, gate-numbering consistency, and doc/content accuracy — generalized from `/sync-workflow`'s existing self-review checklist so it runs on any pragma PR, posting its verdict via `gh pr review --comment` the same way FinanceTracker's `/review` does. Guarded to refuse running outside a checkout of the pragma repo itself, since the plugin manifest has no per-file exclusion mechanism and would otherwise install this command for every plugin consumer.
- **`/gates` Gate 9 — RED-before-GREEN commit order** — synced from FinanceTracker: verifies via git history that a test file was committed strictly before the implementation it exercises, never bundled in the same commit. Generic `scripts/check_tdd_commit_order.py` (path-segment matching, no hardcoded app-name prefixes); warns loudly and exits 2 rather than silently passing if `SCOPED_LAYER_DIRS` still holds the template's default layer names and matches nothing in the adopting project. `/feature` and `/plan` updated for the two-commit (RED, GREEN) task structure this gate depends on. `init.md`/`setup.sh` scaffold the new script into new projects. Old Gate 9 (Architecture & layer-rule compliance) renumbered to Gate 10; `review.md`'s cross-reference updated to match.

### Fixed
- **`scripts/setup.sh` copied `init.md` into every consumer project** — `init.md` itself documents that it should be excluded from the copied set ("it's the plugin's install command, not part of the target project's own pipeline"), but `setup.sh`'s copy step had no matching exclusion, so the shell-script install path leaked it in regardless. Fixed alongside adding the new `pragma-review.md` meta-command, which needed the same exclusion to avoid the identical leak. Found while scoping `/pragma-review`.
- **`scripts/setup.sh` could delete pragma's own tracked files** — the new `init.md`/`pragma-review.md` exclusion added a `rm -f` that would fire against pragma's own repo if `PROJECT_DIR` ever resolved to `REPO_ROOT` (e.g. running the script from inside the pragma repo without an explicit target directory). Added a guard that dies with a clear message instead. Found by `code-review:code-review`.
- **`/feature`'s TDD instruction referenced a non-invokable skill** — a plugin's `enabledPlugins: true` flag in `.claude/settings.json` does not guarantee its skills are actually invocable (`Skill(test-driven-development)` errors with `Unknown skill` in the parent project despite the flag being set, confirmed empirically). Replaced with a self-contained instruction carrying the same substance directly in `feature.md`, no external invocation dependency. `gates.md`'s Gate 9 rationale updated to match. Found by FinanceTracker's 2026-08-16 pipeline review.
- **README Commands table omitted `/parallel-review`** despite the command existing and being used by both pragma and FinanceTracker; merged-PR count callout refreshed from "70+" to "80+" to match FinanceTracker's current count. Found during a README/About audit.

## [1.1.0] — 2026-08-15

### Added
- **Installable as a real Claude Code plugin** — `.claude-plugin/plugin.json` + `marketplace.json`, so `/plugin marketplace add akshaypimprikar/pragma` + `/plugin install pragma@pragma` works with no clone or shell script. Verified locally: `claude plugin validate` passes, and `claude plugin details pragma@pragma` confirms all 16 commands (including the new `/pragma:init`) plus the existing `deterministic-pr-gates` skill — 17 components total — load correctly.
- **`/pragma:init` command** — the plugin-native equivalent of `scripts/setup.sh`, but interviews the user for `CLAUDE.md`'s architecture and key-constraints content and seeds `.claude/context/invariants.md` from the same answers, instead of leaving both as templates to fill in manually — and, unlike the first draft of this command, never overwrites either file if it already exists, matching `setup.sh`'s own guard. Closes the "3 manual edits before your first `/spec`" friction gap that plain `setup.sh` left.
- README: real FinanceTracker screenshots (Dashboard, Accounts) instead of no visuals at all, and a "Why not just Cursor/Windsurf/Copilot's spec mode?" section addressing the obvious comparison directly — CI-enforced gates, cross-session memory, and a real app with 70+ merged PRs are the three things a built-in spec mode doesn't give you

### Fixed
- **`/review`, `/feature`, `/test` had drifted behind FinanceTracker's local, improved copies** — `/review` now logs pre-review fixes to `rejections.md` (not just its own CHANGES REQUESTED verdicts) and posts its verdict as a real GitHub review via `gh pr review --comment`; `/feature` requires both a repeat-call/duplicate test and a missing-required-field test for mutations on shared/persisted entities; `/test`'s Trigger description no longer contradicts `/pr-followup` about running in parallel with `/review`. Caught by a code-review pass on an external plugin-directory listing that described capabilities the shipped template didn't actually have.
- Pre-existing "7 gates" → "9 gates" drift in `feature.md` (`gates.md` itself already documents 9 gates; the prose just never caught up)

## [1.0.0] — 2026-07-31

First versioned release. Pragma has been developed and battle-tested against [FinanceTracker](https://github.com/akshaypimprikar/financetracker-ios) since May 2026; this release captures that history as a baseline.

### Added
- Agent commands layer: 13 Claude Code slash commands covering the full SDLC (`/spec`, `/plan`, `/feature`, `/gates`, `/review`, `/test`, `/bugfix`, `/release`, `/design`, `/pr-followup`, `/sync-workflow`, `/parallel-review`, `/pipeline-review`)
- CI pipeline layer: three GitHub Actions workflow templates (`pr-checks.yml`, `ui-tests.yml`, `release.yml`) for automated PR validation, UI test execution, and release tagging
- Support scripts layer: `select_simulator.py` (deterministic iOS Simulator selection for CI) and `check_coverage.py` (test coverage enforcement)
- `scripts/setup.sh` — one-command installer that copies all three layers into a target iOS project and substitutes placeholders
- Persistent memory layer: `.claude/context/` (invariants, decisions, rejections, feature-log) wired as read/write preambles and postambles across all agent commands
- `/gates` Gate 9 — layer-rule / architecture-compliance checks, including the Patterns checklist (`@Model` shape, relationship `deleteRule`, service statelessness), ported from `/review`'s architecture checklist
- `/gates` abstraction-bloat gate, review-fix loop tips, and a Fowler harness mapping reference
- `/pr-followup` command — auto-chains `/review` then `/test` immediately after a PR opens
- `deterministic-pr-gates` — a standalone, project-agnostic skill extracted from `/gates`
- CI: skip build/test gates when a PR changes no Swift files

### Changed
- Renamed the project from `ios-agent-workflow` to **Pragma**
- Removed auto-merge from `/review` — merging now always requires explicit human action, since GitHub blocks PR authors from approving their own PRs
- `scripts/setup.sh`'s generated CLAUDE.md Merge rule now exempts `release/*`/`hotfix/*` PRs from `/review` and `code-review:code-review` — every commit in those PRs already passed both when it merged into `develop`, so `/release`'s pre-flight test run is the only gate needed there

### Fixed
- `pr-checks.yml` path filter that excluded files it should have covered
- README Mermaid diagram rendering (quoting) and the FinanceTracker repo link

### Documentation
- Full README polish for public launch: badges, Mermaid pipeline diagram, navigation, Getting Started, Quick Start
- `CONTRIBUTING.md` — contribution model, project-adaptation instructions, CI scaffold contribution rules
